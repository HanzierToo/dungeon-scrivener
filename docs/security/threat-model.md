# DungeonScrivener 1.0 security threat model

Status: Task 4 review updated against the corrected 1B contract set and 1C fixtures. This is a threat model and verification plan, not evidence that runtime controls are implemented or that any sandbox is absolute.

## Scope and security goals

DungeonScrivener imports projects and plays exported games in a user's browser. Treat project ZIPs, declared source, arbitrary project files, player-save ZIPs, media, CSS, Markdown, and raw player input as untrusted. The authoring site also renders project content in previews. There are no accounts, server-side game state, collaboration features, or required runtime services.

Protect these assets and properties:

- The editor and player document, their browser origin, and other projects' recovery records.
- Integrity of the active project snapshot and game session. A rejected import must not partially replace either.
- Availability of the browser tab and local storage when processing hostile or oversized input.
- The direct-open export promise: declared local game resources may load, while authored content does not initiate network or unrelated local-file access.
- Authored file bytes and accepted paths. Validation must not silently rewrite or discard recoverable content.

Player saves are portable data, not signed credentials. A player can edit a save file and the local game state. The product has no server authority or anti-cheat boundary. This model does not protect a device from a compromised browser or operating system, malicious extensions, developer tools, or a user who deliberately edits and runs an exported game.

## Trust boundaries and current evidence

The corrected 1B contract set specifies the following boundaries:

1. Project ZIP bytes enter the VFS parser and become a bounded in-memory snapshot. The parser validates raw names, supported ZIP features, CRCs, and actual expanded bytes before publishing the snapshot.
2. The model validates declared structured files and references. Other paths remain opaque bytes. A script, player stylesheet, or managed asset becomes active only through an accepted world reference.
3. A declared JavaScript, Lua, or Python source file is parsed to the documented subset and validated IR. Runtime invocation occurs only when an authored run-script effect names that declared script and that effect is reached. No arbitrary file auto-runs.
4. Script requests, authored effects, event processing, and rules share one provisional engine transaction. The engine commits the complete transition or returns the original snapshot with diagnostics and an error trace.
5. The player forwards choice IDs or raw command text. Raw text goes through command matching and typed capture conversion; the player does not construct trusted typed parameter maps.
6. Host clock and entropy providers are injected at the engine boundary. Scripts have no clock or global random capability. Clock observations and accepted random outcomes are saved as session data.
7. Typing sounds resolve only to local content-addressed WAV files. Markdown becomes a safe AST; player CSS stays within an isolated player surface.
8. A player-save ZIP contains one data-only save.json. A project ZIP preserves accepted project files. A portable game ZIP contains declared playable inputs and trusted runtime artifacts; it does not activate arbitrary project files.

The corrected 1B documents define the contract limits and failure behavior. The [contract README](../contracts/README.md) still identifies the set as under downstream review. Contract/example checks are not runtime evidence: they validate schemas, fixture cross-references, media hashes, and script syntax, but do not execute scripts or game transitions and do not parse arbitrary project ZIPs.

The 1C fixtures now exist. Use [The Lantern Crossing](../../fixtures/linear-three-nodes/README.md) as a small project control and [Tavern at Dusk](../../fixtures/tavern-at-dusk/README.md) as the positive control for reachable JavaScript, Lua, and Python scripts, clock cascades, raw commands, mutable tags, random outcomes, typing WAV, and player saves. Their action transcripts are semantic expectations, not runtime captures. Add adversarial copies or generated ZIPs for the negative checks below; do not edit the fixtures to contain attack payloads.

[Task 1A remains pending acceptance](../feasibility.md). Chromium and Firefox pass the recorded direct-open spike, but Playwright WebKit fails before the main file loads. Safari screenshots show local PNG/WAV loading and blocked probes, but omit the complete story and save round-trip and lack readable full request URLs. These results do not prove production isolation or WebKit support. Keep the gate open for script isolation and export acceptance.

## Corrected contract limits and failure behavior

| Surface | Trust boundary and defined behavior | Security limit or unresolved point |
| --- | --- | --- |
| Reachable script invocation | The world declares each script ID, path, source language, and main entrypoint. Only an authored run-script effect in a choice, command, dialogue option, lifecycle, or rule can invoke it, synchronously at that effect's position. api.request and api.emit changes apply in script order to provisional state. Events enter a shared FIFO queue that drains after the current authored effect list; each triggered rule completes its ordered effects before the next matching rule. Later effects and rules read earlier provisional changes. A script cannot request run-script directly; an emitted event can reach a rule that invokes another declared script. Fixture validation requires its declared scripts to be statically reachable through action, lifecycle, phase-rule, or emitted-event effects. | Per source: 128 KiB UTF-8, 10,000 syntax nodes, 256 function declarations, 32 parameters per function, and nesting depth 64. Unsupported syntax is a compile diagnostic. There is no execution from a filename, extension, or arbitrary file. A missing script reference, parse/IR error, invalid request, runtime error, or budget breach produces diagnostics; the full enclosing transaction is discarded. Fixture reachability and parser checks do not prove runtime isolation or that conditional paths execute. |
| Action transaction and work budgets | A top-level choice, command, dialogue selection, lifecycle transition, clock observation that advances time, and its complete rule/event/script cascade form one transaction. Later effects can read earlier provisional changes. | Per activation: 50,000 IR instructions, 1,000 iterations per while invocation, helper depth 16, 1 MiB allocated string/collection bytes, 1,024 members per collection, 16 KiB per string value, and value nesting depth 32. Per action: 256 script activations, 250,000 IR instructions, 256 script api.request/api.emit calls combined, 10,000 rule executions, 1,000 queued event occurrences, 10,000 applied effects, and 20,000 trace records. A breach or invalid request aborts the whole action and returns the original snapshot, diagnostics, and error trace. Effects, tags, inventory, game time, rule guards, seeded RNG state, and saved unseeded outcomes do not partially commit. External host entropy cannot be rolled back. |
| Raw command text | PlayerInput.command-text carries rawText to matchCommandText, then dispatchPlayerInput. Matching normalizes NFC, trims and collapses Unicode whitespace, lowercases without locale, matches the current inherited command set, and captures one whole token per placeholder. String captures preserve normalized NFC spelling and case; number, integer, boolean, and enum captures use the specified strict conversions. Quoted and multi-token captures are unsupported. Conversion failure is no-match. Hidden false-condition commands are excluded; disabled commands remain candidates. | Authored patterns are limited to 256 characters each, but the public rawText string has no byte, character, or token limit. No oversize-input failure behavior is defined. No-match, ambiguity, and disabled resolution preserve the snapshot and consume no action time. Ambiguous command IDs are sorted by code-point order; canonical/alias order does not choose a winner. This remains a denial-of-service contract gap for very large input. |
| Persisted entity tags | EntityInstance.tags are initial tags. Session entityTags is a mutable set copied for every known entity, updated idempotently by add-tag/remove-tag, and read by conditions and api.hasTag. Save data must include every known entity ID exactly once, with sorted unique tags allowed by that entity's definition. | Malformed, unknown, missing, disallowed, duplicate, or unsorted saved tag entries fail semantic validation. Save import validates the whole archive/session before replacing the active session. A structurally valid, edited save can still change a player's tags; saves have no authenticity mechanism. |
| Host clock and saved clock state | The host supplies epoch milliseconds, visibility, focus, and tick/visibility-change/focus-change/resume events to observeClock. The engine reads no browser globals. Either hidden or unfocused is inactive. Pause adds no inactive time; bounded-catch-up adds at most the world-configured maxCatchUpMilliseconds. Resume is treated as an inactive interval even without a final hide event. Clock state saves the last observation, activity flags, and inactive interval start. | Per-action worlds ignore clock inputs and store null epoch baselines. A timestamp earlier than the saved baseline produces a diagnostic, adds no time, and resets the baseline to the supplied timestamp. Elapsed saves require a baseline and a consistent active/inactive interval. Malformed saves fail before session replacement. There is no global maximum for a forward active-time jump or a maximum world-configured catch-up value; local wall time is not an authoritative clock. ClockInput's public type also does not define a runtime range/failure rule for negative, fractional, or non-finite values. |
| Randomness provider and replay data | createGameEngine requires a host nextUint32 source. Seeded sessions also require a uint32 start seed; zero normalizes to 0x6d2b79f5. Seeded worlds do not consume the host provider; they use the specified xorshift32 session state. Unseeded worlds use the injected uniformly distributed uint32 source and save each accepted draw with ordinal, source script ID, operation, bounds, and value. Scripts cannot reach a global random API. Seeded state and unseeded draw records commit only with the action. | Integer ranges are inclusive and may contain at most 2^32 values. Rejection sampling stops after 64 raw draws for one request; exhaustion is a runtime diagnostic and aborts the transaction. Invalid random bounds are also runtime failures. An aborted unseeded action leaves no outcome record, while the external provider has advanced, so retry can yield a different draw. xorshift32 and the game provider are for story variation and replay, not cryptographic secrets. The contract requires uint32 provider output but does not state the failure behavior for a provider returning a float, negative value, or out-of-range integer. It requires a uint32 start seed but does not specify the createSession failure result for a missing or invalid seed. randomOutcomes has no cumulative count limit; save ZIP input is capped at 8 MiB, so long sessions can outgrow that import cap. |
| Typing-sound assets | Each mapping names a case-sensitive standardized KeyboardEvent.code or one of the defined key groups, a content hash, and volume from 0 through 1. Exact-key mapping takes precedence over group mapping. Every referenced hash must resolve under assets/sha256 and identify WAV bytes. Duplicate targets are model errors. The explicit fallback is an asset or silence. | Missing or unplayable mapping media uses the fallback; fallback failure is silent. Playback is a UI effect, causes no network request, and changes no game state. The general ZIP limits cap one project file at 64 MiB and total expanded project files at 256 MiB. No WAV duration, sample-rate, channel-count, decode-memory, or playback-rate limit is defined. The fixture checker includes typing-sound hashes in its playable paths, while [archive-save-fingerprint.md](../contracts/archive-save-fingerprint.md) describes a narrower media set; align that fingerprint contract before claiming save compatibility binds the WAV bytes. |
| Project ZIP import and export | readProjectZip accepts store/deflate only. It validates actual bytes and CRC, rejects unsupported features and unsafe/colliding paths, and preserves accepted path spelling and file bytes. On failure or timeout it discards the partial snapshot and preserves the source ZIP for recovery/export. writeProjectZip emits store/deflate entries; the archive index is an API result, not an archive member. | Import limits: 128 MiB ZIP input, 256 MiB expanded total, 64 MiB per file, 20,000 entries, 1,024 UTF-8 path bytes, 255 bytes per path segment, 16 MiB structured JSON, depth 64, 30 seconds per project, and 5 seconds per member. Unsafe absolute/traversal paths, invalid UTF-8, non-NFC paths, duplicate/case-colliding names, encryption, split archives, Zip64, symlinks/special files, unsupported compression, and CRC mismatch fail import. Accepted project ZIP export retains arbitrary files byte-for-byte and inert. |
| Player-save ZIP import | A save ZIP has exactly one save.json member, uses store/deflate, and is data only. Import checks project ID, author gameVersion, engineVersion, and recomputed playable-content fingerprint, then checks state references and mode-specific session fields before replacement. No v1 migration is automatic. | The input ZIP cap is 8 MiB and JSON depth is 64. Compatibility or validation failure leaves the active session unchanged. The budget text does not clearly state an expanded save.json byte/member limit separate from compressed input, nor a cumulative randomOutcomes cap. Do not claim the compressed input cap alone bounds decompression. |
| Portable game export | Export includes declared playable data, validated/compiled script IR, the trusted runtime, and referenced local assets. Authored strings must remain data; unrelated project files remain inert. | Safe context-specific serialization and direct-open request checks are required. A generated game ZIP is distinct from a byte-preserving project ZIP and the data-only player-save ZIP. The 1A gate remains pending for WebKit/Safari evidence. |

## Contract gaps for owner review

These items are intentionally recorded without changing contracts or runtime:

- Raw command patterns are limited to 256 characters, while PlayerInput.rawText has no byte/character/token cap or oversize failure behavior. Define a hard input cap and rejection result before claiming bounded raw-command processing.
- Player-save ZIP has an 8 MiB compressed-input cap and JSON depth 64, but its maximum expanded save.json bytes are not explicit. Confirm whether the 16 MiB structured JSON limit applies to saves, then set a hard inflate cap that cannot be bypassed by compression.
- The injected entropy provider is required to return uniform uint32 values, but invalid return values have no specified failure contract. Specify rejection without coercion and transaction rollback. Seeded sessions require a uint32 start seed, but createSession's failure behavior for a missing or invalid seed is also unspecified.
- The unseeded randomOutcomes list has no cumulative count/byte cap, even though save ZIP input is capped at 8 MiB. Define how long sessions remain saveable and replayable.
- Clock data defines backwards-time behavior and author-configured inactive catch-up, but no maximum active forward delta, global catch-up ceiling, or invalid ClockInput range behavior. This is local story timing, not an authoritative time source.
- Typing WAV data inherits the project file byte cap, but has no audio duration, sample-rate, channel-count, decode-memory, or repeated-playback limit. The fixture checker includes typing WAVs in playable paths; the fingerprint contract's prose needs to name them explicitly.
- The engine API permits caller-supplied ArchiveLimits, while the budgets document calls its values contract maxima. Keep per-call settings at or below those ceilings; clarify whether callers may only tighten them.

## Release verification checklist

- [ ] Project ZIP import enforces raw path, CRC, supported-feature, actual expanded-byte, entry-count, JSON, and timeout limits before snapshot activation. Failure preserves the source ZIP and discards partial state.
- [ ] Project ZIP export preserves every accepted path and file byte. Arbitrary files stay inert and are absent from portable game export.
- [ ] Every runnable script is declared and reference-validated; fixture scripts exercise a reachable effect path. JS/Lua/Python source respects all parser limits and compiles to validated IR only; runtime tests prove isolation after the 1A gate is accepted.
- [ ] Script effects, event/rule cascades, and clock-triggered scripts stay within action-wide budgets. Late failure returns the original snapshot, including tags, inventory, time, guards, RNG state, and saved random outcomes.
- [ ] Raw command matching uses one canonical matcher, strict one-token captures, deterministic ambiguity, and no-action behavior for no-match/ambiguous/disabled input. Resolve the missing rawText cap.
- [ ] Player-save import validates the full session, entityTags, clockState, RNG fields/logs, compatibility values, and archive before replacement. Oversize expansion has a hard cap.
- [ ] Clock and entropy host inputs are checked at their boundary. Forward-clock and invalid-provider gaps are resolved or explicitly accepted as local behavior.
- [ ] Typing sounds use verified local WAV hashes, exact-key/group precedence, configured fallback, and silent fallback failure. Decoder/playback limits are addressed.
- [ ] Markdown consumes safe AST. CSS cannot affect authoring chrome or request undeclared resources.
- [ ] Export serialization has adversarial string coverage, and direct-open request traces are captured in Chromium, Firefox, and WebKit. Task 1A's pending Safari/WebKit evidence is closed before claiming broad browser support.
