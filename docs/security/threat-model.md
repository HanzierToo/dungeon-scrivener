# DungeonScrivener 1.0 security threat model

Status: Task 4 review updated against the amended 1B contracts and 1C fixtures. The contracts README still marks the set under downstream review. This is a threat model and verification plan, not evidence that runtime controls are implemented or that any sandbox is absolute.

## Scope and security goals

DungeonScrivener imports projects and plays exported games in a user's browser. Treat project ZIPs, declared source, arbitrary project files, player-save ZIPs, media, CSS, Markdown, and raw player input as untrusted. The authoring site also renders project content in previews. There are no accounts, server-side game state, collaboration features, or required runtime services.

Protect these assets and properties:

- The editor and player document, their browser origin, and other projects' recovery records.
- Integrity of the active project snapshot and game session. A rejected import must not partially replace either.
- Availability of the browser tab and local storage when processing hostile or oversized input.
- The direct-open export promise: declared local game resources may load, while authored content does not initiate network or unrelated local-file access.
- Authored file bytes and accepted paths. Validation must not silently rewrite or discard recoverable content.

Player saves are portable data, not signed credentials. A player can edit a save file and the local game state. The product has no server authority or anti-cheat boundary. This model does not protect a device from a compromised browser or operating system, malicious extensions, developer tools, or a user who deliberately edits and runs an exported game.

## Trust boundaries and current evidence

The corrected 1B contract set specifies the following boundaries:

1. Project ZIP bytes enter the VFS parser and become a bounded in-memory snapshot. The parser validates raw names, supported ZIP features, CRCs, and actual expanded bytes before publishing the snapshot.
2. The model validates declared structured files and references. Other paths remain opaque bytes. A script, player stylesheet, or managed asset becomes active only through an accepted world reference.
3. Each declared JavaScript, Lua, or Python source must compile to exactly one validated IR in a `CompiledScriptBundle`, with matching ID, path, language, and `main`; missing, extra, duplicate, or mismatched IR blocks engine creation. The host-injected `ScriptExecutorApi` synchronously receives only the selected IR, invocation origin, remaining limits, and capability callbacks when a reached authored `run-script` effect is processed. No arbitrary file auto-runs.
4. Script requests, authored effects, event processing, and rules share one provisional engine transaction. The executor never receives a mutable session snapshot. The engine commits the complete transition or returns the original snapshot with diagnostics and an error trace. Unexpected executor exceptions and malformed instruction reports are fatal transaction failures.
5. The player forwards choice IDs or raw command text. Raw text goes through command matching and typed capture conversion; the player does not construct trusted typed parameter maps.
6. Host clock and randomness providers are injected at the engine boundary. Scripts have no clock or global random capability. Seeded sessions use a saved xorshift32 seed/state; unseeded outcomes are logged and replay-verified. Clock observations and random history are bounded session data.
7. Typing sounds are projected as content-hash references and resolved through `MediaAssetApi`, which verifies bytes without exposing VFS paths. Only validated RIFF/WAVE assets are playable; Markdown becomes a safe AST and player CSS stays within an isolated player surface.
8. A player-save ZIP contains one data-only save.json. A project ZIP preserves accepted project files. A portable game ZIP contains declared playable inputs and trusted runtime artifacts; it does not activate arbitrary project files.

The amended 1B contracts define the limits and failure behavior summarized below. The [contract README](../contracts/README.md) still identifies the set as under downstream review. Contract/example checks are not runtime evidence: they validate schemas, fixture cross-references, media hashes, and script syntax, but do not execute scripts or game transitions and do not parse arbitrary project ZIPs.

The 1C fixtures now exist. Use [The Lantern Crossing](../../fixtures/linear-three-nodes/README.md) as a small project control and [Tavern at Dusk](../../fixtures/tavern-at-dusk/README.md) as the positive control for reachable JavaScript, Lua, and Python scripts, clock cascades, raw commands, mutable tags, random outcomes, typing WAV, and player saves. Their action transcripts are semantic expectations, not runtime captures. Add adversarial copies or generated ZIPs for the negative checks below; do not edit the fixtures to contain attack payloads.

[Task 1A remains pending acceptance](../feasibility.md). Chromium and Firefox pass the recorded direct-open spike, but Playwright WebKit fails before the main file loads. Safari screenshots show local PNG/WAV loading and blocked probes, but omit the complete story and save round-trip and lack readable full request URLs. These results do not prove production isolation or WebKit support. Keep the gate open for script isolation and export acceptance.

## Amended contract limits and failure behavior

| Surface | Trust boundary and defined behavior | Security limit or unresolved point |
| --- | --- | --- |
| Reachable script invocation and executor boundary | The world declares scripts, but the engine accepts only an exact `CompiledScriptBundle` match: one validated IR for each declaration with matching ID/path/language/entrypoint. Mismatch blocks engine creation. Only a reached authored `run-script` effect selects IR and synchronously calls the host-injected `ScriptExecutorApi`. The executor receives IR, caller origin, clamped remaining budgets, and callbacks for `read`, `hasTag`, typed `request`, `emit`, and randomness. It receives no mutable snapshot. Scripts have no DOM, storage, network, filesystem, clock, reflection, dynamic import, eval, or native-package capability; they cannot invoke another script directly. `request` applies validated effects to provisional state in source order; events drain FIFO after the current effect list. | Per source: 128 KiB UTF-8, 10,000 syntax nodes, 256 function declarations, 32 parameters per function, and nesting depth 64. Per activation: at most 50,000 instructions and the clamped activation limits below. Engine checks reported instruction counts and trace allowance. Runtime fault, capability rejection, thrown executor exception, malformed/over-limit executor result, or budget breach fails the complete action and returns original snapshot plus diagnostics/error trace. This specifies the capability contract, not a proven hostile-code isolation implementation; the 1A browser gate remains open. |
| Action transaction and work budgets | A top-level choice, command, dialogue selection, lifecycle transition, clock observation that advances time, and its complete rule/event/script cascade form one transaction. Later effects can read earlier provisional changes. | Per activation: 50,000 IR instructions, 1,000 iterations per while invocation, helper depth 16, 1 MiB allocated string/collection bytes, 1,024 members per collection, 16 KiB per string value, and value nesting depth 32. Per action: 256 script activations, 250,000 IR instructions, 10,000 total `api.*` capability calls (including reads, tag checks, random calls, requests, and emits), 256 `api.request`/`api.emit` effect-event submissions combined, 10,000 rule executions, 1,000 queued event occurrences, 10,000 applied effects, and 20,000 total trace records. A breach or invalid request aborts the whole action and returns the original snapshot, diagnostics, and error trace. Effects, tags, inventory, game time, rule guards, seeded RNG state, and saved unseeded outcomes do not partially commit. External host entropy cannot be rolled back. |
| Raw command text | Player input sends only a choice ID or raw text; the player does not supply trusted typed captures. The engine checks UTF-16 validity and limits before normalization, then NFC-normalizes, collapses Unicode whitespace, and applies locale-independent lowercase. One whole token maps to each placeholder; strict typed conversion failure is no-match. Hidden commands are excluded and disabled matches remain disabled resolutions. | Raw text: 4,096 UTF-8 bytes, 1,024 Unicode scalar values, 128 normalized tokens. Effective action set: 256 commands, 32 patterns/command, 16 parameters/command; each pattern 4,096 UTF-8 bytes and 128 tokens; at most 1,048,576 token comparisons/match. Bounds are inclusive. Malformed UTF-16 or over-limit raw input returns `invalid-input` with diagnostic, no truncation/prefix match, no time advance, and no session mutation. An over-limit effective command set is model-invalid and blocks play. No-match, ambiguous, and disabled resolution also preserve session/time. |
| Persisted entity tags | EntityInstance.tags are initial tags. Session entityTags is a mutable set copied for every known entity, updated idempotently by add-tag/remove-tag, and read by conditions and api.hasTag. Save data must include every known entity ID exactly once, with sorted unique tags allowed by that entity's definition. | Malformed, unknown, missing, disallowed, duplicate, or unsorted saved tag entries fail semantic validation. Save import validates the whole archive/session before replacing the active session. A structurally valid, edited save can still change a player's tags; saves have no authenticity mechanism. |
| Host clock and saved clock state | Only the host supplies `ClockInput`; scripts cannot read or set it. Inputs carry epoch milliseconds, visibility, focus, and tick/visibility-change/focus-change/resume events. Either hidden or unfocused is inactive. Pause adds no inactive time; bounded catch-up adds at most `maxCatchUpMilliseconds`. Resume is an inactive interval even without a final hide event. Elapsed clock observations that advance time and resulting rules/scripts share one atomic action. | Timestamps must be safe integers from 0 through `Number.MAX_SAFE_INTEGER`; `maxCatchUpMilliseconds` is at most 86,400,000. Repeated timestamps are no-op. Earlier-than-baseline timestamps, invalid visibility/focus, arithmetic overflow, or invalid start baselines are rejected with a diagnostic and no session mutation; values are never coerced/clamped. Per-action worlds ignore clock inputs and keep null baselines. Valid active forward gaps have no smaller elapsed-delta cap; credited game time cannot exceed the safe-integer bound. This is local story time, not authoritative time. Save import validates clock-state consistency before replacement. |
| Randomness providers and replay data | Seeded sessions use a supplied validated uint32 seed or request one from `seededSeedSource`; missing/invalid seed availability fails session creation, and zero normalizes to `0x6d2b79f5`. Seeded sessions use xorshift32 and persist both normalized initial seed and current state. Unseeded sessions need no provider until a random call; then entropy is required unless a replay source is supplied. Replay takes precedence, checks ordinal/source script/operation/bounds and returned range, never falls back to entropy, and the harness must detect unused extra records. Scripts cannot reach a global random API. Accepted outcomes commit with the action; failed transactions do not commit the log, though external entropy cannot roll back. | Inclusive integer ranges contain at most 2^32 values; rejection sampling allows 64 raw uint32 draws/request. Exhaustion or missing entropy/replay fails the action. Maximum unseeded history is 16,384; the 16,384th record may commit and a later draw fails rather than truncating. Canonical session JSON and expanded save.json are each capped at 8 MiB; session overflow fails transition/save, and import rejects before replacement. Saves retain complete history. Randomness is for story variation/replay, not secrets. One gap remains: contracts require providers to return uniform uint32 values but do not define failure for a malformed runtime return (for example NaN or 4,294,967,296). |
| Player media and typing-sound assets | `PlayerView.typingSounds` always supplies mappings and fallback as content-addressed references. The player must obtain bytes using `MediaAssetApi.resolveAsset(assetId)`, which verifies the digest and returns media type/length/bytes without a VFS path. Referenced assets must be valid managed WAVs before play/export: consistent RIFF/WAVE sizes/alignment, one `fmt ` and `data` chunk, PCM or IEEE float, 1-2 channels, 8-192 kHz, PCM 8/16/24/32-bit or float32. Exact key beats group mapping; duplicate targets reject validation. Missing/hash-mismatched/malformed media blocks play/export. Runtime unavailability or browser decode/play failure tries configured fallback; fallback failure is diagnostic and silent. No network or game-state mutation. Typing WAVs and fallback are included in the playable fingerprint. | Project ZIP limits cap an asset at 64 MiB and total expansion at 256 MiB. The WAV format is now bounded by encoding/rate/channels/bit depth, but duration, decoder memory, and repeated/concurrent playback are not capped. This leaves a browser-resource exhaustion gap for a valid long WAV. |
| Project ZIP import and export | readProjectZip accepts store/deflate only. It validates actual bytes and CRC, rejects unsupported features and unsafe/colliding paths, and preserves accepted path spelling and file bytes. On failure or timeout it discards the partial snapshot and preserves the source ZIP for recovery/export. writeProjectZip emits store/deflate entries; the archive index is an API result, not an archive member. | Import limits: 128 MiB ZIP input, 256 MiB expanded total, 64 MiB per file, 20,000 entries, 1,024 UTF-8 path bytes, 255 bytes per path segment, 16 MiB structured JSON, depth 64, 30 seconds per project, and 5 seconds per member. Unsafe absolute/traversal paths, invalid UTF-8, non-NFC paths, duplicate/case-colliding names, encryption, split archives, Zip64, symlinks/special files, unsupported compression, and CRC mismatch fail import. Accepted project ZIP export retains arbitrary files byte-for-byte and inert. |
| Player-save ZIP import | A save ZIP contains exactly one `save.json` member, uses store/deflate, and never executes source. The importer enforces archive/member bounds, JSON depth, full schema/semantic validation, project/game/engine/fingerprint equality, session references, mode-specific RNG/clock fields, and replay-history integrity before replacing the active session. Saves are editable, unsigned data, not credentials. | ZIP input and expanded member are each capped at 8 MiB; canonical serialized session is capped at 8 MiB; JSON depth is 64. Unseeded history is capped at 16,384, inventory at 10,000 stacks, conversation contexts at 64, and dialogue history at 10,000 IDs per context. Saved epoch timestamps and per-action game time are safe integers from zero through `Number.MAX_SAFE_INTEGER`. Do not truncate when a limit is reached: the operation that would exceed a collection/session cap fails atomically, encoding an oversized save fails, and import rejects before replacing the active session. No v1 migration is automatic. |
| Portable game export | Export includes declared playable data, validated/compiled script IR, the trusted runtime, and referenced local assets. Authored strings must remain data; unrelated project files remain inert. | Safe context-specific serialization and direct-open request checks are required. A generated game ZIP is distinct from a byte-preserving project ZIP and the data-only player-save ZIP. The 1A gate remains pending for WebKit/Safari evidence. |

## Contract gaps for owner review

These items are intentionally recorded without changing contracts or runtime:

- The unseeded entropy source is typed to produce uniformly distributed uint32 values, but the contracts do not define failure behavior if it returns `NaN`, a fraction, a negative integer, or `2^32`. Seeded session creation does define failure when no valid supplied/host seed is available. Reproduction: inject `unseededRandomSource.nextUint32: () => 4294967296` and invoke `api.randomInt(1, 3)`; whether the engine rejects without coercion and rolls back, masks the value, or records an invalid result is unspecified.
- The WAV validator now constrains format, rate, channels, and bit depth, and asset bytes are hash-verified through `MediaAssetApi`; it does not bound duration, decode allocation, or overlapping playback. Reproduction: import a valid near-64-MiB mono 8 kHz PCM WAV and trigger its key mapping repeatedly while playback overlaps. The project byte cap still permits a long asset and decoder/player memory growth has no contract ceiling.
- A valid active clock observation may span a very large forward interval. Timestamp and resulting game time are safe-integer bounded and inactive catch-up is capped at one day, but no narrower active-delta cap exists. Reproduction: with an active elapsed world and a time threshold rule, submit a valid timestamp near `Number.MAX_SAFE_INTEGER`; the contract permits a large time advance and resulting cascade. Story time is local and not authoritative, but behavior is a product/security decision if accidental host jumps must be bounded.

## Release verification checklist

- [ ] Project ZIP import enforces raw path, CRC, supported-feature, actual expanded-byte, entry-count, JSON, and timeout limits before snapshot activation. Failure preserves the source ZIP and discards partial state.
- [ ] Project ZIP export preserves every accepted path and file byte. Arbitrary files stay inert and are absent from portable game export.
- [ ] Every runnable script is declared and reference-validated; fixture scripts exercise a reachable effect path. JS/Lua/Python source respects all parser limits and compiles to validated IR only; runtime tests prove isolation after the 1A gate is accepted.
- [ ] Script effects, event/rule cascades, and clock-triggered scripts stay within action-wide budgets. Late failure returns the original snapshot, including tags, inventory, time, guards, RNG state, and saved random outcomes.
- [ ] Raw command matching enforces byte/scalar/token and matching-work bounds; malformed or over-limit input returns `invalid-input` without truncation or session/time changes.
- [ ] Player-save import validates the full session, entityTags, clockState, RNG fields/logs, compatibility values, and archive before replacement. Enforce the 8 MiB compressed input and expanded member limits plus the 8 MiB canonical session limit.
- [ ] Clock and entropy host inputs are checked at their boundary. Preserve clock input on invalid/backwards values; resolve or explicitly accept large active forward jumps and malformed entropy-source returns.
- [ ] Typing sounds use verified local WAV hashes, exact-key/group precedence, configured fallback, and silent fallback failure. Measure/decide duration, decode-memory, and repeated-playback bounds.
- [ ] Markdown consumes safe AST. CSS cannot affect authoring chrome or request undeclared resources.
- [ ] Export serialization has adversarial string coverage, and direct-open request traces are captured in Chromium, Firefox, and WebKit. Task 1A's pending Safari/WebKit evidence is closed before claiming broad browser support.
